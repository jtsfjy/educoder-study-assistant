## 1. 定位

你这轮的三个事实拼出了完整结论：

1. **"实训区已连接"** → 探针找到了编辑器，`requestEditor` 有回包；
2. **"注入还是无反应"** → 写入调用返回了，但页面上看不到变化；
3. **评测结果 0/1 不匹配，而你人工验过代码是对的** → 评测器拿到的**不是生成的那份代码**。

第 3 条是关键：说明写入没有进入平台真正读取的那份状态。上一轮的三条假设（shadow DOM、contenteditable、受控组件）里，第三条还差最后一层——**页面只认真实键入事件**（`isTrusted=true`）。这也解释了你之前提到的"防粘贴"：粘贴被拦、合成输入被忽略。

`execCommand('insertText')` 能改 DOM、能触发 `input`，但事件 `isTrusted=false`；平台若在 `beforeinput`/`input` 上校验 `isTrusted`，就会丢弃。**这是合成事件的天花板，换 API 绕不过去，只能换事件来源。**

## 2. 修复：加一级"受信任输入"

新增 `src/background/trusted-input.ts`：用 CDP 往页面里打字。

```
content: focus 编辑器 + 全选
   ↓
background: chrome.debugger.attach(tabId, '1.3')
   ↓  Input.insertText({ text: code })     ← 浏览器输入管线，isTrusted=true
   ↓  chrome.debugger.detach(tabId)
content: 再回读一次，与期望代码比对
```

写入流程变成两级：

| 级别 | 手段 | 何时使用 |
|---|---|---|
| 1 | 实例 API / `execCommand` / 原生 setter | 常规优先，回读一致即结束 |
| 2 | CDP `Input.insertText` | 仅当第 1 级回读不一致，或拿不到编辑器实例 |

代价与边界：

- 新增 `debugger` 权限，**重载扩展时 Edge 会提示新增权限**，需要你确认；
- attach 期间浏览器顶部出现"正在调试此浏览器"提示条，detach 后消失（一次注入约几百毫秒）；
- 不会抓取页面数据，只做一次文本插入；
- 设置页有 `useTrustedInput` 开关，可关闭第二级。

## 3. 附带修正

- `inject()` 现在把失败信息分成三段：常规写入失败原因（策略名 + 编辑器类型 + 六个探测位）+ 受信任输入失败原因 + 回读差异说明。任何一段失败都能定位到具体环节；
- 受信任输入后**必须回读一致才判定成功**，仍然失败就明说"页面可能在回滚"，不假装写进去了。
