## 1. 根因：判据只有一条通道

旧版本 `writeEditor()` 的判定链是"写实例 → 从同一个实例读回 → 相等即成功"。这条链在三种情况下会给出**假成功**：

| # | 场景 | 现象 | 旧代码为什么看不出来 |
|---|---|---|---|
| 1 | 页面里留着上一题/隐藏标签页的编辑器实例 | 写入无反应，面板报「已写入」 | CM5/CM6/ACE/Monaco **完全没有可见性闸门**，隐藏实例照样被选中；写它、读它，永远一致 |
| 2 | 页面里同时有两个可见编辑器（模板框 + 真编辑器） | 写到模板框上，屏幕没变 | 跨帧只按"回读代码最长"挑帧，长度不是正确性 |
| 3 | 编辑器带残留代码，框架不认 API 写入 | 旧代码 + 新代码拼接，评测读旧首行 | 没有第二视角，也没有"先清空/全选"这一步 |

用户报的"OJ 型"同时踩中 1 和 3：平台拦复制，说明它只认真实输入；编辑器里带残留代码；而隐藏实例让整套校验自己骗自己。

## 2. 改动

### 2.1 目标选取（探针）

- 所有编辑器类型走同一条**可见性闸门**：`isConnected` + 宽 ≥ 80 / 高 ≥ 18 + `display/visibility/opacity` + `checkVisibility({checkOpacity, checkVisibilityCSS})`；
- 候选打分：可见（1000）+ 面积（≤300）+ 有渲染文本（120）+ 离评测按钮的距离（≤260）+ 文档长度（≤120）+ 类型权重；
- 选出唯一目标后**固定 `pinnedHost`**，写/读都用它，页面重渲染导致元素失联才重挑；
- 终端只认真正的 xterm 结构（`.xterm-rows` / `.xterm-screen` / `.xterm-helper-textarea`），类名带 `terminal` / `console` 的结果面板不再被当成终端。

### 2.2 写入判据（shared/inject-check.ts，纯函数）

两个独立视角：

```
文档值（实例 getValue / 元素 value）
屏幕渲染文本（.CodeMirror-code / .cm-content / .ace_text-layer / .view-lines / innerText）
```

| 观测 | 判据 | 行为 |
|---|---|---|
| 文档一致 + 渲染命中特征行（首/中/末行） | `verified` | 通过 |
| 文档一致、渲染没变 | `render-stale` | 失败，降级受信任输入 |
| 文档一致、渲染文本读不到 | `render-blind` | canvas/虚拟化编辑器，按可见性 + 文档视角 |
| 文档不一致 | `doc-mismatch` | 失败，降级 |
| 目标不可见 | `editor-hidden` | 不写 |
| 写入前后本来就一致 | `noop` | 通过 |

渲染采样前先**滚到顶部**：否则"滚动"本身会被当成"内容变了"，把没生效的写入判成成功。

### 2.3 独立复核（编排）

写入报成功 ≠ 结束。`inject()` 现在会另起一次 `requestEditor()` 复核，一致才报「已写入」。这是为了掐掉"写入与回读是同一条通道"的自我确认。

### 2.4 受信任输入

- `insertText` 前先 **Ctrl+A**（浏览器级全选，不受 `user-select:none` 影响）→ 整篇替换，残留代码不叠加；
- 文档完全没变化时降级为「Ctrl+A + Backspace 清空 + 逐键键入」，代码 ≤ 1200 字符（每字符两次 CDP 往返，再长会拖到分钟级）。

### 2.5 诊断

- 诊断区新增「写入校验」行：本次写入走通的路径 + 判据；
- 「候选」行现在带 `doc=` / `ren=` 长度与 `[隐藏]` 标记，`*` 是本次选中的目标；
- `INJECT_MISMATCH` 附带判据、可见性、候选摘要。

## 4. 下一轮需要的真机信息

OJ 型题目上点「自检」和「自动解题」，把这两行发回即可定位剩余问题：

1. `候选`：谁被选中（`*`），有没有 `[隐藏]` 的实例，`doc=` / `ren=` 各多少；
2. `写入校验`：`verified` / `render-stale` / `render-blind` / `doc-mismatch` 中的哪一个。

如果仍是 `doc-mismatch` 且策略是 `codemirrorX.setValue`：说明该 OJ 编辑器不是 CM/ACE/Monaco 里的任何一个，需要它的 outerHTML（F12 选中编辑器元素 → Copy outerHTML → 前 50 行），下一轮加专用适配器。

---

**结论**：假成功不是"写入没生效"，是"校验只问了自己"。现在判据有第二个视角、复核有第二条通道、残留代码先清空，OJ 型实训区的三种失败形态各自有对应处理。
