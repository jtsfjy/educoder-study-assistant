## 1. 你观察到的两件事，分别对应两个真问题

### 1.1 "屏幕有代码输入，但还是报错" + `61 → 61 字`

前端读到的屏幕文本长度输入前后没变，但你眼睛看到代码进去了——**说明 xterm 用的是 canvas 渲染**。`div.terminal.xterm` 里如果挂的是 canvas，`.xterm-rows` 里就没有文字，`innerText` 只能是 61 字这种固定量。

**结论：对终端做"屏幕文本校验"这条路本身是错的。** 不是输入没进去，是判据读不到输入。

修复：终端不再做屏幕内容校验。键入完成后直接进入评测，**由评测结果判定**。终端的真实性由"评测通过/不通过"来回答，这比任何 DOM 探针都可靠。

### 1.2 MySQL 实验要先登录临时服务器

这是本轮的关键信息：**题目不是纯编辑器题，是 MySQL 实验**，开始要先连临时服务器：

- 用户 `root`，密码 `123123`，地址 `127.0.0.1`

之前所有失败都指向同一处：SQL 从来没在数据库里执行过。终端里空的，评测自然 0/1。

**修复：终端前置命令（prelude）**

- 设置页新增「终端前置命令（每行一条）」文本框与开关；
- 默认值已按你给的信息填好：`mysql -h127.0.0.1 -uroot -p123123`；
- 终端任务执行顺序变为：**先跑前置命令（登录）→ 等 1.5s → 逐键键入代码 → 回车**；
- 关掉开关即回到"直接键入代码"，不影响普通编辑器题。

### 1.3 提示词同步修正

终端已登录的情况下，模型如果还把 `mysql -u root -p...` 写进代码里，评测照样不过。所以生成前会自动往约束里加一条：

> 当前终端已登录数据库（前置命令：…）。只输出 SQL 语句，不要包含登录或连接命令。
