## 2. 测试连接异常：两个独立根因

你贴的三条记录里其实是两个不同故障，混在一起很难判断：

### 2.1 `16:58 / 17:04 Failed to fetch` —— 域名没授权

manifest 的 `host_permissions` 只列了 7 个常见厂商域名。**填列表以外的网关时，service worker 的 fetch 被浏览器直接拦掉，错误就是 `Failed to fetch`**，和 Key 无关。

修复：

- manifest 增加 `optional_host_permissions: ["https://*/*", "http://*/*"]`；
- 设置页在点"保存 / 测试连接"时（用户手势内）对当前 baseUrl 的 origin 调 `chrome.permissions.request`，弹窗允许即生效；
- 后台在 fetch 前先 `chrome.permissions.contains` 检查，没授权就抛 `NO_HOST_PERMISSION` 并写清域名——不再让浏览器抛那句无信息的 `Failed to fetch`；
- fetch 抛 `TypeError` 时统一转成 `NETWORK_ERROR`，消息里带完整 endpoint。

### 2.2 `16:55 鉴权失败（401）… your api key: ****ce9c is invalid` —— 这是真的 401

401 由提供商返回，说明请求**确实到达了服务器**，只是那台服务器不认这个 Key。最常见的原因是 Key 与 baseUrl 不是同一家（拿 A 家 Key 调 B 家地址），其次是 Key 里混进了空格/不可见字符。

修复（可诊断性，不是绕过）：401 消息现在带上**本次请求的 endpoint 与模型名**，并把"Key 与接口地址是否同一家"写在提示里——照着这两项核对，30 秒能定位。

> 结论：如果 401 仍然出现，请把面板里那行含 `请求 https://…，模型 …` 的完整文本发我。若 endpoint 与你填的地址不一致，那就是配置问题；若一致，就是 Key 本身的问题（可去提供商控制台复制新 Key 重试）。

## 7. 风险备注

- `optional_host_permissions` 写的是通配 `https://*/*`：这是让"任意自定义网关"可用的唯一办法，代价是首次会对用户弹一次授权。只在用户点击保存/测试时请求，不静默提权。
- 授权是按 origin 记的：换域名要重新授权一次。
- 401 属于服务端判定，扩展侧能做的是把"请求打到哪、用的哪个模型"摊开，不能替提供商验 Key。
