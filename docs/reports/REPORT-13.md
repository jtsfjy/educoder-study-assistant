## 1. 这次失败说明什么

你的报错：

```
策略 terminal.trusted · 编辑器 terminal
受信任输入后回读仍不一致：终端屏幕里没出现写入的语句
```

链路已经走到最后一步：终端识别对了、焦点给了、CDP 附上了、`Input.insertText` 也执行了，**但屏幕没有变化**。所以问题只剩两个可能：

1. **输入没落进终端**——`insertText` 只对普通可编辑元素可靠；xterm 这种靠 `keydown` 驱动的终端可能只认键盘事件；
2. **输入进去了但不回显**——SQL 终端往往只回显执行结果，不回显语句本身；此时"屏幕里有没有我写的语句"这个判据本身是错的。

两种都可能，所以这轮把两个都覆盖掉。

## 2. 修复

| 改动 | 内容 |
|---|---|
| 逐键键入 | 新增 `mode: 'keys'`：对每个字符发 `keyDown`（带 `text`）+ `keyUp`，换行发 `Enter`。xterm 走的就是这条路 |
| 自动降级 | 终端首次 `insertText` 后屏幕无变化 → 自动改用逐键键入再试一次 |
| 判据改为"屏幕是否变化" | 终端不再要求"屏幕里出现语句"；**屏幕内容与键入前不同**即认为输入被接受（兼容"只回显结果、不回显语句"的终端） |
| 回车兜底 | 逐键模式结束后同样补一次 `Enter`（无论代码是否以换行结尾） |
| 错误信息带数字 | 失败时输出 `终端屏幕 812 → 812 字`，一眼看出是"完全没动"还是"动了但内容不对" |

状态行会出现这几步：

```
常规写入未生效，改用受信任输入…
终端没有回显，改用逐键键入…        ← 仅在 insertText 无效时出现
已写入 16 行（受信任输入 · terminal · 已回车执行）
```
