## 1. 本轮新增：本地答案库

**为什么放 background**：`hardenStorage()` 把 `chrome.storage.local` 收紧成 `TRUSTED_CONTEXTS`，content script 读不到——这是密钥隔离的同一道闸。答案库因此不进 content 侧，全部走消息：

| 消息 | 方向 | 作用 |
|---|---|---|
| `answer:get` | top → bg | 按指纹+语言取缓存，命中则更新 `updatedAt` 与 `hits` |
| `answer:put` | top → bg | 只存**评测通过**的代码 |
| `answer:drop` | top → bg | 缓存未通过时立即失效，避免反复踩同一个坑 |
| `answer:stats` | options → bg | 设置页显示"已缓存 N 道题" |
| `answer:clear` | options → bg | 清空（content script 调会被拒） |

**键与生命周期**（`src/shared/answers.ts`，纯函数，可单测）：

- 键 = `${fingerprint}:${language}`，指纹已含标题/题面/语言/模板，模板一改自动失效；
- 只存 `verdict: 'passed'`，未通过的不入库；
- 容量 200 条，超出按 `updatedAt` 保留最近的（`trimAnswers`）；
- 30 天未使用视为过期，下次读取时删掉（`isStale`）；
- 读改写串行化（`withLock`），并发 solve 不会互相覆盖。

**解题流程变化**（`orchestrator.solve()`）：

```
命中缓存 → 注入 → 回读校验 → 点评测 ─通过→ 结束（零 token）
                          └─未通过→ 删缓存 → 现场生成 → 重试轮
未命中 → 生成 → 注入 → 点评测 → 通过 → 写缓存
```

面板会明确写"答案库命中（不消耗 token）"；缓存失配时会说明"缓存代码未通过，已失效；改为现场生成…"，不会让人以为模型没跑。

## 6. 风险备注

- 答案库只在本机，不做云端共享；但"同一道题被同学共用答案"的风险仍取决于平台是否做提交比对——本扩展不改变这一点。
- 缓存的有效性完全依赖指纹稳定：如果平台每次渲染题面都塞入随机 ID/时间戳，指纹会抖，缓存命中率会掉。真机上如果命中率低，下一轮改成"指纹 + 标题 + 语言"降级键。
- 清空答案库是立即生效的本地操作，没有撤销。
